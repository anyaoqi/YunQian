# 01 产品需求文档（PRD）

## 1. 核心概念（领域模型）

| 概念 | 说明 | 关系 |
| --- | --- | --- |
| **书签 Bookmark** | 一条收藏，核心字段为 URL | 属于 0..1 个集合；拥有 0..N 个标签 |
| **集合 Collection** | 树形容器，等价「文件夹」，可嵌套 | 自引用父子；一条书签只归属一个集合 |
| **标签 Tag** | 扁平关键字，跨集合横向串联 | 与书签多对多 |
| **视图 View** | 当前筛选条件的组合（集合 + 标签 + 关键词 + 排序） | 前端状态，V3 起可保存为智能集合 |

设计原则：**集合管"放在哪"（唯一归属），标签管"是什么"（多重属性）**。

## 3. V1 用户故事与验收标准

### US-1 导入浏览器书签
**作为**重度书签用户，**我要**上传从 Chrome/Edge 导出的 `bookmarks.html`，**以便**一次性迁移历史收藏。

验收：
- 支持 Chrome / Edge / Firefox / Safari 导出的 Netscape HTML。
- HTML 中的文件夹层级映射为集合树；`TAGS` 属性映射为标签。
- 同一 URL 已存在时默认跳过（可选覆盖），返回 `{imported, skipped, collections, tags}` 统计。
- 1000 条书签导入耗时 < 3s（单事务批量写入）。

### US-2 快速新增书签
**作为**开发者，**我要**粘贴 URL 后自动带出标题，**以便**3 秒内完成收藏。

验收：
- URL 必填且格式校验（仅 http/https）；标题为空时可点击「抓取标题」自动填充。
- 标签输入支持逗号/回车分隔，不存在的标签自动创建。
- 保存后列表顶部立即出现该条目。

### US-3 组织与检索
**作为**用户，**我要**按集合、标签、关键词组合过滤，**以便**在上千条收藏中快速定位。

验收：
- 侧边栏点击集合 → 仅显示该集合（含子集合）下的书签。
- 点击标签 → 与集合条件为「与」关系叠加。
- 搜索框对 `title / url / description / note` 做 LIKE 匹配，300ms 防抖。
- 分页默认 24 条/页，返回 `total` 供分页器使用。

### US-4 编辑与删除
验收：编辑弹窗预填现有值；删除需二次确认；删除后计数与标签统计同步刷新。

### US-5 备份导出
验收：`GET /api/export` 下载包含集合、标签、书签的完整 JSON，可作为备份与迁移凭证。

## 4. 关键交互规则

1. **URL 规范化**：去除首尾空格、补全协议（`example.com` → `https://example.com`）、去掉常见跟踪参数（`utm_*`、`fbclid`）。
2. **去重判定**：以规范化后的 URL 全等为准（V1），V2 引入域名+路径相似度提示。
3. **删除集合**：其下书签不删除，移动到「未分类」（`collection_id = NULL`）；子集合同步上提。
4. **孤儿标签**：无任何书签引用的标签在统计中显示为 0，可手动删除，不自动清理。
5. **默认集合**：`collection_id = NULL` 视为「未分类」，侧边栏固定展示。

## 6. 边界与异常

| 场景 | 处理 |
| --- | --- |
| 导入文件非法/超 20MB | 400，提示格式或体积限制 |
| 抓取标题超时（>5s）或站点拒绝 | 静默失败，保留用户手填标题 |
| 重复 URL 新增 | 409，前端提示「已收藏」并给出跳转 |
| 空库首次进入 | 展示引导卡片：新增第一条 / 导入书签 |
