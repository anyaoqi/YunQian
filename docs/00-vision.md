# 00 项目愿景与竞品分析

## 1. 背景与问题

浏览器原生书签的三个结构性缺陷：

1. **组织维度单一**：只有树形文件夹，一个网址无法同时属于「前端」和「待读」。
2. **检索能力弱**：只能按标题模糊匹配，无法按描述、备注、标签、时间组合过滤。
3. **知识不沉淀**：收藏后没有备注、没有阅读状态、没有回顾机制，收藏夹变成「数字垃圾场」。

跨设备同步、团队共享、失链腐烂（link rot）同样缺位。

## 2. 产品愿景

> 打造一个「网址导航 + 知识库」双形态的收藏系统：
> 对外是**一眼可达的导航面板**，对内是**可检索、可注释、可复用的个人知识库**。

三条设计主线：

- **导航优先**：首页即高密度可视化面板，2 秒内点开常用站点。
- **组织自由**：集合（树）+ 标签（网）双轴，多维交叉过滤。
- **知识增值**：备注、摘要、阅读状态、快照，让链接不只是链接。

## 3. 目标用户

| 画像 | 场景 | 核心诉求 |
| --- | --- | --- |
| 开发者 / 技术研究者 | 文档、库、教程、issue 长期积累 | 标签检索、代码类站点分组、快速粘贴收藏 |
| 内容创作者 / 学生 | 选题素材、参考资料、灵感库 | 封面预览、备注摘要、按主题聚合 |
| 团队（V4） | 共享工具箱、竞品库、SOP 链接 | 协作集合、权限、评论 |
| 重度书签用户 | 已有数千条浏览器书签 | 一键导入、去重、批量整理 |

## 4. 竞品分析

| 维度 | Raindrop.io | Toby | Pocket | 浏览器书签 | **云签** |
| --- | --- | --- | --- | --- | --- |
| 组织模型 | 集合 + 标签 | 集合 + 标签（偏标签页） | 标签 | 文件夹 | 集合树 + 标签 |
| 视图 | 列表/卡片/瀑布流 | 卡片 | 阅读列表 | 列表 | 列表/卡片（V2 起） |
| 全文检索 | Pro 付费 | 无 | 有 | 无 | V4（SQLite FTS5 + 向量） |
| 数据自主 | 云端托管 | 云端托管 | 云端托管 | 本地 | **自托管、单文件 SQLite** |
| 离线可用 | 有限 | 有限 | 部分 | 是 | 是（本地优先） |
| AI 能力 | 无 | 无 | 摘要 | 无 | V4 自动打标/摘要/语义检索 |
| 价格 | 订阅 | 订阅 | 订阅 | 免费 | 开源自托管 |

### 差异化结论

云签不追求功能超越，而在三点上取胜：

1. **数据自主 + 零门槛部署**：一个 `.db` 文件，可备份、可迁移、可 Git 管理导出的 JSON。
2. **导航面板形态**：不是"稍后读"清单，而是替代新标签页的入口。
3. **AI 原生规划**：语义检索与自动打标从架构层预留（`embedding` 表、`content_snapshot` 表）。

## 5. 成功指标

| 阶段 | 指标 |
| --- | --- |
| V1 | 能导入 ≥1000 条浏览器书签且导入耗时 < 3s；增删改查全链路可用 |
| V2 | 单条收藏平均操作耗时 < 5s；列表 1 万条滚动无卡顿 |
| V3 | 扩展一键收藏成功率 > 99%；失链检测覆盖全库 |
| V4 | 语义检索 Top5 命中率 > 80% |

## 6. 非目标（明确不做）

- 不做全网爬虫式内容聚合（版权与成本）。
- V1-V3 不做移动端原生 App，响应式 Web 覆盖。
- 不做社交信息流、点赞关注等社区功能。
